# data_model.md

Loan application system. Supabase (Postgres). 8 tables.
Model: XGBoost, 21 input features, target `risk_label` (1 = risky, ~8% of training rows).
Table creation in Supabase is done separately; this file is the spec.

## 2. Model input (21 features, exact order)

The backend must build this row in this exact order and units.

| # | feature | source / formula |
|---|---|---|
| 1 | owns_property | `assets.owns_property` (0/1) |
| 2 | annual_income | `employment.annual_income` |
| 3 | credit_amount | `loan_applications.credit_amount` |
| 4 | monthly_installment | EMI formula from `credit_amount`, `tenure_months`, `interest_rate` |
| 5 | income_type | `employment.income_type`, ordinal-encoded |
| 6 | education | `customers.education`, ordinal-encoded |
| 7 | marital_status | `customers.marital_status`, ordinal-encoded |
| 8 | residence_type | `customers.residence_type`, ordinal-encoded |
| 9 | occupation | `employment.occupation`, ordinal-encoded |
| 10 | family_size | `customers.family_size` |
| 11 | ext_score_1 | `credit_profiles.ext_score_1`, null -> median |
| 12 | ext_score_2 | `credit_profiles.ext_score_2`, null -> median |
| 13 | ext_score_3 | `credit_profiles.ext_score_3`, null -> median |
| 14 | enquiries_last_year | `credit_profiles.enquiries_last_year` |
| 15 | age_years | (today - `customers.dob`) in years, 1 decimal |
| 16 | employed_years | (today - `employment.start_date`) in years, 1 decimal; 0 if `start_date` is null |
| 17 | credit_to_income | `credit_amount / annual_income` |
| 18 | installment_to_income | `monthly_installment / annual_income` (annual income, not monthly) |
| 19 | ext_score_1_missing | 1 if `ext_score_1` was null, else 0 |
| 20 | ext_score_2_missing | 1 if `ext_score_2` was null, else 0 |
| 21 | ext_score_3_missing | 1 if `ext_score_3` was null, else 0 |

EMI formula: `r = interest_rate / 12 / 100`, `n = tenure_months`,
`EMI = P * r * (1 + r)^n / ((1 + r)^n - 1)` where `P = credit_amount`.

Median fallbacks (from training): ext_score_1 = 0.505994, ext_score_2 = 0.566198, ext_score_3 = 0.535276.

Categorical encoding: load `encoder` (sklearn OrdinalEncoder) and `medians` from `tree.joblib`.
Encoder column order: income_type, education, marital_status, residence_type, occupation.
Unknown value -> -1.

Not model inputs: gender, dependents (family_size is used instead), existing loans, credit cards, balance, credit_score.

## 3. Allowed text values (must match the encoder exactly)

- income_type: Businessman, Commercial associate, Maternity leave, Pensioner, State servant, Student, Unemployed, Working
- education: Academic degree, Higher education, Incomplete higher, Lower secondary, Secondary / secondary special
- marital_status: Civil marriage, Married, Separated, Single / not married, Widow
- residence_type: Co-op apartment, House / apartment, Municipal apartment, Office apartment, Rented apartment, With parents
- occupation: Accountants, Cleaning staff, Cooking staff, Core staff, Drivers, HR staff, High skill tech staff, IT staff, Laborers, Low-skill Laborers, Managers, Medicine staff, Private service staff, Realty agents, Sales staff, Secretaries, Security staff, Unknown, Waiters/barmen staff

## 4. View: customer_features

One row per customer. Returns customer-side model inputs only.
Backend adds loan fields (3, 4, 17, 18) and the missing flags (19-21).

Columns: customer_id, owns_property, annual_income, income_type, education, marital_status, residence_type, occupation, family_size, ext_score_1, ext_score_2, ext_score_3, enquiries_last_year, age_years, employed_years.

Joins: customers + employment + assets + credit_profiles on `customer_id`.

## 5. Seed data

- Build 30 to 50 customers by sampling rows from `X_train` / `X_test` in `tree.joblib`.
- Decode encoded columns back to text with `encoder.inverse_transform`.
- Split each row across tables: income and categories -> `employment` / `customers`; scores and enquiries -> `credit_profiles`; `owns_property` -> `assets`.
- `ext_score_N_missing = 1` -> store `ext_score_N` as null.
- `dob` = today - `age_years`. `start_date` = today - `employed_years`; null when `employed_years` = 0.
- Skip extreme rows: keep `annual_income` and `credit_amount` between the 5th and 95th percentile.
- Mix: about 60% clearly low-risk (`risk_label` = 0, high ext scores), about 40% clearly risky (`risk_label` = 1, low ext scores) so the demo shows both outcomes.
- Add 1 to 2 `accounts` per customer. Add `existing_loans` and `credit_cards` rows for display only.
- Use fake mobile numbers and emails.
- Keep each sampled row's `credit_amount` and `monthly_installment` for use as demo application inputs.
